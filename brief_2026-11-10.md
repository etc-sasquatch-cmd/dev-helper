## Decisions made that are not in the SPEC

- One music profile only (row 1 of `music_profile`), not several named ones.
- Music follows the timer: plays while a phase runs, pauses on pause, stops when idle or when
  the phase is set to Silence. The same source across two phases keeps playing with no restart.
- A single video loops. A playlist loops and skips up to three unplayable videos in a row.
- A link with both a video and a playlist is saved as the playlist, except auto-mixes
  (`list=RD...`), Watch Later, and Liked, which cannot be embedded: those save the single video.
- The recap prompt is an inline panel, not a pop-up, so it never covers the player. In compact
  mode the window grows by 160 px while the panel shows and shrinks back afterwards.
- All pop-up messages appear at the top of the window, away from the player.
- Opening any dialog (skill, preset, music) pauses the music until it closes.
- A source that fails is not retried until something changes (pause and resume, or a new phase).
- Spotify is dropped. The user wanted Spotify to play inside the widget; the version built was
  only a remote control for a separate Spotify app. In-widget playback would need Spotify's
  Web Playback SDK and an untested copy-protection check in WebView2. The user chose
  YouTube only instead.

## Findings to carry forward

**YouTube restrictions on this PC or network**
- Error 151 is not in YouTube's official error list. Here it came with the player's own text
  "This video is restricted. Please check the Google Workspace administrator and/or the network
  administrator restrictions." The Lofi Girl live stream `jfKfPfyJRdk` triggers it.
- A second ordinary video (`dQw4w9WgXcQ`) failed with error 150.
- The user's own link (`MfmapkolO-g`) and the test video `M7lc1UVf-VE` play fine.
- So some videos will not play on this machine, and the app cannot fix that. It shows a clear
  message and carries on.

**NiceGUI and the native window**
- JS to Python: `emitEvent(name, data)` in the page, `ui.on(name, handler)` in Python.
- Python to JS: `client.run_javascript(...)` without awaiting. Only do it after
  `client.on_connect` has fired.
- A button can run JavaScript directly in the click with
  `.on("click", handler, js_handler="() => { ...; emit(); }")`. The Play button for blocked
  autoplay uses this.
- Native mode serves on `127.0.0.1:8000` when that port is free. `ui.run(port=...)` fixes the port.
- The window process is a child of the `python.exe` that was launched, so look at the whole
  process tree when checking ports or CPU.
- `app.get(path)` adds a plain web route to the same local server.

**If Spotify ever comes back**
- Spotify's dashboard rejects `http://127.0.0.1/...` without a port as "not secure", although
  its documentation allows it. `http://127.0.0.1:47821/spotify/callback` was accepted.
- Development-mode apps need the owner to have Premium. Tick only "Web API" for remote control;
  in-widget playback would also need "Web Playback SDK" and the `streaming` permission.
- The user created a Spotify developer app during this session. It is unused now and can be
  deleted in the Spotify dashboard.

## Environment notes

- The assistant's real runs use `FOCUSDECK_DATA_DIR` pointing at a scratch folder, seed the
  database from Python (including a running focus block, so restart recovery starts the
  music without a click), and screenshot only the FocusDeck window with `PIL.ImageGrab`.
- Those runs play sound through the speakers. Seed `music.volume` low.
- The Git Bash tool breaks on long inline Python with quotes. Write the script to a file and
  run the file.
- `core.autocrlf` is on. Files written with LF show as modified until Git refreshes; check
  with `git diff --ignore-cr-at-eol` before worrying.
